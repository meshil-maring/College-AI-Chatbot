# Student Enrollment Schema Proposal v2

- **Status:** Design proposal; not executable DDL
- **Related decision:** `docs/architecture/ADR-ENROLLMENT-002.md`
- **Database operations:** None performed

## Design summary

Keep `public.students` as the stable identity/profile. Introduce four additive objects to separate admission episodes, academic placement, institutional identifier ownership, and event history. Do not switch existing application reads/writes to this model until the compatibility and security gates are complete.

## 1. `student_enrollments`

One row is one admission episode at one institution for one program.

Proposed columns:

- `enrollment_id uuid` — primary key, generated by the database.
- `student_id uuid NOT NULL` — FK to `students.student_id`, restrictive delete behavior.
- `institution_id uuid NOT NULL` — FK to `institutions.institution_id`, restrictive delete behavior.
- `program_id uuid NULL` — FK to `programs.program_id`; nullable only while an application is unresolved/pending. Program ownership must be checked through its department.
- `predecessor_enrollment_id uuid NULL` — self-FK linking readmission, program change, or destination transfer episode to its predecessor.
- `admission_kind text NOT NULL` — constrained values such as `initial`, `readmission`, `transfer_in`, `program_change`, `legacy_snapshot`.
- `lifecycle_status text NOT NULL` — constrained to the lifecycle proposed in ADR-ENROLLMENT-002.
- `approval_status text NOT NULL` — `pending`, `approved`, or `rejected`; distinct from account registration approval.
- `admission_effective_on date NULL` — evidence-backed academic admission date; may remain unknown for a quarantined legacy snapshot.
- `closed_effective_on date NULL` — evidence-backed closure date for a terminal transition.
- `expected_graduation_date date NULL` — cannot precede the effective admission date when both are known.
- `student_number_identifier_id uuid NULL` — FK to the student's institution identifier record of kind `student_number`.
- `register_identifier_id uuid NULL` — FK to the student's institution identifier record of kind `register_number`.
- `university_roll_identifier_id uuid NULL` — FK to the student's institution identifier record of kind `university_roll_number`.
- `version bigint NOT NULL DEFAULT 1` — optimistic concurrency token.
- `created_at timestamptz NOT NULL DEFAULT now()` and `updated_at timestamptz NOT NULL DEFAULT now()`.

Required checks/guards:

- Student and institution identity are required and immutable.
- The selected identifier records must belong to the same student and institution and have the expected kind.
- Program must belong to the enrollment institution through `programs -> departments`.
- A transition to `active` requires approval and verified mandatory fields; the database routine must reject an invalid transition.
- Terminal states require a closure effective date for new operational transitions. Legacy snapshots may preserve unknown dates with explicit provenance rather than inventing them.
- Do not add the recommended one-operational-enrollment partial unique index until D4 is approved.

## 2. `student_institution_identifiers`

Represents institution-issued identifier ownership independently of enrollment episodes.

Proposed columns:

- `identifier_id uuid` — primary key.
- `student_id uuid NOT NULL` — FK to `students.student_id`, restrictive deletion.
- `institution_id uuid NOT NULL` — FK to institution, restrictive deletion.
- `kind text NOT NULL` — `student_number`, `register_number`, or `university_roll_number`.
- `display_value text NOT NULL` — original identifier text, preserving leading zeros.
- `normalized_value text NOT NULL` — initially `trim(display_value)`; no case folding unless policy is confirmed.
- `verified_at timestamptz NULL`, `verified_by uuid NULL`, `source text NOT NULL`, `created_at timestamptz NOT NULL DEFAULT now()`.

Proposed uniqueness:

- Unique `(institution_id, kind, normalized_value)` to prevent an identifier from being assigned to a different student.
- Reuse by the same student across readmission episodes is represented by referencing the same identifier row, not by duplicating the assignment.
- Identifier values are never silently reassigned to another student. Historical identifier records are retained.

Database guards must verify that `verified_by` is an authorized actor and that enrollment references point to an identifier row with the matching student, institution, and kind. The account email is not stored as an institutional identifier.

## 3. `student_academic_placements`

Represents the student's academic position over an effective period, separate from admission.

Proposed columns:

- `placement_id uuid` — primary key.
- `enrollment_id uuid NOT NULL` — FK to enrollment, restrictive deletion.
- `academic_year_id uuid NOT NULL` — FK to `academic_years`.
- `semester_id uuid NOT NULL` — FK to `semesters`; semester must belong to the referenced academic year.
- `class_section_code text NULL` — optional class label, not a subject-section FK.
- `attempt_number integer NOT NULL DEFAULT 1` — positive integer for repeated semester/year placement.
- `starts_on date NOT NULL`, `ends_on date NULL` — half-open interval `[starts_on, ends_on)`.
- `mapping_source text NOT NULL`, `mapping_status text NOT NULL` — preserve mapping provenance; ambiguous legacy mappings cannot drive operational authorization.
- `version bigint NOT NULL DEFAULT 1`, `created_at timestamptz NOT NULL DEFAULT now()`, `updated_at timestamptz NOT NULL DEFAULT now()`.

Required guards:

- Academic year and semester must belong to the enrollment institution and semester/year pairing.
- Ordinary placement intervals for an enrollment must not overlap; implement with an appropriate exclusion constraint or serialized transaction, based on available extensions and the final lifecycle semantics.
- `attempt_number > 0`; `ends_on IS NULL OR ends_on > starts_on`.
- Promotions, repeats, and class changes create new rows; they do not overwrite historical placement.
- Subject section membership remains represented by `faculty_attendance_rosters` and the existing section/course-offering model.

## 4. `student_enrollment_events`

Append-only event ledger for transitions and historical provenance.

Proposed columns:

- `event_id uuid` — primary key.
- `enrollment_id uuid NOT NULL` — FK to enrollment, restrictive deletion.
- `placement_id uuid NULL` — FK to placement when relevant.
- `event_sequence bigint NOT NULL` — monotonically allocated per enrollment under a row lock; unique with `enrollment_id`.
- `operation_id uuid NOT NULL` — idempotency key; globally unique unless a documented tenant scope is chosen.
- `event_type text NOT NULL` — constrained vocabulary covering admission creation/approval/rejection/activation, leave/resumption, graduation/withdrawal, transfer, placement creation/promotion/repetition, identifier assignment, correction, and `legacy_snapshot`.
- `lifecycle_before text NULL`, `lifecycle_after text NULL`, `approval_before text NULL`, `approval_after text NULL`.
- `effective_on date NULL` — null only where the historical effective date is unknown or not applicable.
- `recorded_at timestamptz NOT NULL DEFAULT now()`.
- `actor_user_id uuid NULL` — FK to `users.id` with restrictive deletion; actor accounts should be retained or anonymized.
- `source text NOT NULL`, `reason text NULL`, `transfer_group_id uuid NULL`, `corrects_event_id uuid NULL`, `details jsonb NULL`.

Required guards:

- Unique `(enrollment_id, event_sequence)` and unique `operation_id`.
- An operation ID replay with identical input returns the prior result; the same ID with different input fails.
- State change, event insert, security audit entry, and reconciliation occur in one transaction.
- Browser roles receive no write grants. An append-only trigger rejects ordinary UPDATE/DELETE; grants and trigger behavior must be tested together.
- `details` is bounded and must not contain credentials, secrets, or unnecessary personal data.

## Cross-object and migration constraints

1. Do not infer actual admission dates from `students.enrollment_date`; current registration code sets that field at registration time.
2. Do not update `students.institution_id` to represent a transfer.
3. Preserve existing `student_attendance`, `student_results`, `student_result_items`, `test_results`, `faculty_attendance_rosters`, and `student_notifications` keys and history.
4. Before associating an academic record to an enrollment/placement, require a deterministic mapping supported by its institution, program/year/semester, date, roster, and source provenance. Quarantine ambiguity.
5. Existing result-visibility triggers must be revised so a current placement change does not automatically alter the publication state of historical results.
6. Tenant validation must run at database boundary and in backend service logic. Service-role use is not a substitute for ownership checks.
7. New RPCs need explicit ACLs for every overload, qualified object references, and hardened `search_path`. Do not grant direct browser table writes.
8. Existing security ACL snapshots conflict. Verify current installed catalog state before applying any security or enrollment migration.

## Not included / not yet approved

- Executable SQL migration.
- Final partial unique indexes for operational enrollment/placement cardinality.
- Cutover of authentication, student context, attendance, results, roster reconciliation, notifications, AI context, or frontend caches.
- Data backfill, deployment, or remote Supabase changes.
