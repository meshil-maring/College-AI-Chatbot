## Scope and evidence standard

Starting references: [blocker matrix](SECURITY_CONTAINMENT_BLOCKER_EVIDENCE_MATRIX.md), [routine inventory](SECURITY_CONTAINMENT_ROUTINE_INVENTORY.md), [independent review](SECURITY_CONTAINMENT_INDEPENDENT_REVIEW.md). The [source JSON](SECURITY_CONTAINMENT_SOURCE_EVIDENCE.json) is a navigation aid, independently checked against the cited SQL/Python/PowerShell bodies. Latest definitions, replacements, the renamed implementation and both invitation overloads are distinguished. The 44 include six trigger functions and internal helpers, not 44 independent HTTP endpoints. There are 24 empty-path and 20 public-path definers. Only `manage_academic_master_record` contains dynamic SQL in these latest bodies. No latest definer contains an `auth.uid()` reference; that fact alone is not a vulnerability in a service-mediated design.

“Confirmed source defect” means the missing check or incorrect operation order is visible in the code. It does **not** establish deployed reachability, successful exploitation or observed database behavior. “Potential” means exploitation depends on a privilege, connection, race or trust condition not established here. “Catalog/runtime required” means source cannot decide the acceptance question. Severity describes realistic impact if the stated conditions hold; confidence concerns the source finding, separately from exploitability.

Only local reads, source searches, hashes, Markdown checks and official PostgreSQL documentation were used. No application imports, SQL execution, database-dependent tests, Supabase connections, Docker commands, deployment or push occurred. The existing source builder/verifier was not run. PostgreSQL 17 documentation supplies semantics, not target-version evidence.
